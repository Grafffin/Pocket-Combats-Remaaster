### Файлы web/battle/js/

- **Игровая логика без DOM** (работает и в Node, и в Edge Function): `data.js` (общие данные), `classes.js`, `stats.js`, `items-data.js` (предметы, аффиксы, уники), `monsters.js`, `world-data.js` (зоны, сложности), `engine.js` (бой, `makeRng(seed)`), `items.js`, `progression.js` (уровни, миграции героя, `CHAR_VERSION` 7), `economy.js`, `world.js` (мир от времени `now`, `TICK_MS` 10000), `actions.js` (все действия героя вне боя), `version.js` (версия сборки, `__BUILD__` подставляет CI).
- **Клиент и онлайн:** `config.js` (URL Supabase и публичный anon key), `auth.js` (вход, гость), `cloud.js` (облачное сохранение, `cloud.act`, `cloud.call`, `cloud.locked`), `presence.js` (кто на локации), `chat.js`, `battles.js` (список «Бои», общие бои), `lockstep.js` (синхронизация общего боя), `worldsync.js` (общие монстры мира, таблица `world_mobs`), `market-ui.js` (рынок игроков).
- **Интерфейс:** `ui-kit.js` (модалки, тосты, `storage`), `item-ui.js`, `battle-ui.js`, `hub.js` (мир, герой, NPC, `predict` оптимистичных действий), `bag-ui.js`, `forge-ui.js`.

Правила: модули без DOM не должны трогать `window`/`document`; всё в общем пространстве имён `PC`; сборки нет, зависимостей нет (supabase-js с CDN).

## 3. Игровые механики (коротко, детали в PROJECT_CONTEXT и GDD)

- Бой тиками по 10 с, действие по нажатию, автобой и автоохота. Рост чисел `growth(L)=1.12^(min(L,40)-1)`, защита `K/(K+def)`.
- 4 класса (воин, берсерк, охотник, маг), 10 слотов, 26 типов × 7 тиров, 8 редкостей (7 — уникальная), качество 0–100, заточка +15, ранги ★0–5, добродетели-сеты, перековка, сумка 48, сундук аккаунта 300.
- 6 зон + деревня, 8 ступеней сложности (до Пытки V), открываются победой над последним боссом (`final: true`, сейчас Лич). 12 уников.
- Ресурсы: кузнечные (камни, свитки защиты и перековки, руда, кожа, эссенция; флаг `forge` в `items-data.js`) лежат в `char.materials` без лимита, остальные (зелья, эликсиры, травы) стаками `{ stack, count }` в сумке, до `data.STACK_MAX` (200) в ячейке. Доступ только через `items.matCount/matAdd/matTake/matRoom`. `CHAR_VERSION` 7.
- Сохранение: в облаке `characters` (герой, сундук, `rev`); локально `pc-character-v3`, `pc-stash`, `pc-ui-prefs`, резерв `pc-cloud-backup-v1`.

## 4. Архитектура онлайна

### 4.1 Supabase
Проект `https://nyyeikzqcckovplxlbda.supabase.co`. Anon key публичный и лежит в `config.js`. Гостевой (анонимный) вход включён, подтверждение email выключено. `service_role` ключ не нужен и не просится: он доступен Edge Function автоматически.

### 4.2 Серверная правда (Edge Function `game`)
Подробно `docs/SERVER_AUTHORITY.md`. Суть: функция исполняет **тот же** JS (`sync.sh` копирует его в `_game/`), клиент шлёт намерения `{op, args, rev, v}`, сервер со своим rng и временем применяет их и пишет `characters`. Версия `v` сверяется, при расхождении ответ `version` и клиент перезагружается. Бои: `fightStart`/`fightJoin`/`fightEnd` (таблица `game_fights`, миграция 0013): сервер выдаёт seed, монстра и снимок бойца, в конце переигрывает историю боя и сам начисляет награду; подделка награды не даёт. Переходы (`travel`, `cancelTravel`, `arrive`) считает сервер. Замок (миграция 0014): у `authenticated` отобрано право писать `characters`, клиент хранит локальную копию как кэш (`cloud.locked`).
Оптимистичные действия: без rng/now (`Date.now`, `Math.random`) клиент показывает результат сразу (`predict` в `hub.js`) и откатывается при отказе сервера. Токен кэшируется на 5 минут.
Состояние: этапы 1–6 закончены, 0013 и 0014 применены, живой смоук на Supabase проходит.

### 4.3 Общий бой (lockstep)
До 10 игроков, `lockstep.js`. Считает хозяин, остальные воспроизводят события детерминированно. В каждом ходу отпечаток состояния `cs`, пульс хозяина, правило «двух хозяев» (больше ходов побеждает), расчёт может перейти к другому участнику. Решение пользователя: удар срабатывает сразу при нажатии в рамках хода (как в одиночном), вступивший бьёт сразу. Рассинхрон раньше возникал из-за разных версий клиента, поэтому есть версия сборки.

### 4.4 Рынок игроков
Миграция 0012, функции `market_list/buy/cancel/claim` (security definer, блокировка строки, сверка `rev`), клиент вызывает через `PC.cloud.call`. Комиссия 5%, лот 3 дня, до 20 лотов. Защита от дюпа: `market_owner` + проверка `item_on_market` в `characters_validate`.

### 4.5 Версия сборки и кэш
`pages.yml` подставляет `GITHUB_SHA[:10]` в `version.js` и `?v=` в `index.html`. `sw.js`: страница всегда из сети, файлы с `?v=` кэшируются навсегда, картинки из кэша с обновлением в фоне. Если правишь кэширование, меняй имя `CACHE`.

```bash
node web/battle/tools/lockstep-test.js            # общий бой

SERVER=1 NODE_PATH=$(npm root -g) node web/battle/tools/e2e-coop.js   # то же с подставной функцией game
node web/battle/tools/server-smoke.js <версия>    # живой Supabase; только в Actions после деплоя
```

Первые три обязательны перед любым PR, затрагивающим `engine/lockstep/actions/ops` (их же гонит `tests.yml`). Из контейнера агента `supabase.co` недоступен (403 прокси), живые проверки только через смоук в Actions. Playwright и Chromium в облачной сессии предустановлены.

## 7. CI и деплой

- `tests.yml` — на PR (пути `web/**`, `supabase/functions/**`, `.github/workflows/**`).
- `pages.yml` — на push в `main`: тесты → подстановка версии → `sync.sh` + `supabase functions deploy game --project-ref nyyeikzqcckovplxlbda` (если есть секрет `SUPABASE_ACCESS_TOKEN`, он есть) → `server-smoke.js` → Pages.
- Секрет `SUPABASE_ACCESS_TOKEN` лежит в GitHub Secrets. Не печатай его и не коммить.
- Мердж PR в `main` = выкладка клиента и функции одним коммитом.
